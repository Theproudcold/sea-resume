# 模板库增强设计

- 日期：2026-03-30
- 主题：模板页预览、实时缩略图、筛选排序与使用流程增强
- 状态：已确认设计，待进入实现计划

## 1. 背景

当前模板页 `src/views/TemplateGallery.vue` 只完成了基础卡片展示，存在以下明显问题：

- 预览弹窗仍是“开发中”占位，无法实际查看模板效果。
- 模板卡片依赖 `thumbnail` 字段，但当前模板元数据未提供真实缩略图来源。
- “使用此模板”使用 `confirm/cancel` 混充二选一交互，动作语义不清晰。
- 模板页没有分类、搜索、排序能力，模板数量增加后会迅速失控。
- 模板组件映射在多个视图中重复维护，后续扩展容易出现同步问题。

本次设计目标是在不推翻现有模板页路由与卡片心智的前提下，完成模板页的产品化增强。

## 2. 目标与非目标

### 2.1 目标

- 在模板页提供可实际使用的完整模板预览能力。
- 为每个模板卡片提供基于演示数据的实时缩略图，而非静态图片占位。
- 重构“使用此模板”流程，提供明确且可预期的动作选择。
- 提供分类、关键词搜索、排序切换能力。
- 支持从工作台与编辑页进入模板页，并根据入口调整可用动作。
- 记录模板最近使用时间，用于排序。

### 2.2 非目标

- 不在本次实现中新增模板种类。
- 不引入服务端模板数据源，模板筛选与排序均在前端本地完成。
- 不将模板缩略图持久化为 Base64 或图片文件。
- 不重构现有导出、编辑器、工作台主流程。
- 不将模板页改造成常驻侧栏或工作台内嵌面板。

## 3. 选定方案

本次采用“升级型图库”方案：

- 保留独立模板页路由 `/templates`。
- 页面主体为“筛选工具条 + 模板卡片网格”。
- 模板卡片直接显示实时缩略图。
- 点击 `预览` 打开大预览弹窗。
- 点击 `使用此模板` 打开明确选择框。

选择该方案的原因：

- 与当前页面结构最接近，改造成本最低。
- 用户仍沿用“浏览卡片 -> 预览 -> 使用”的心智模型。
- 对移动端改造压力明显小于双栏 Explorer 方案。
- 当前模板数量仅为 5 个，没必要上更重的展示架构。

## 4. 信息架构与页面布局

### 4.1 路由

- 模板页继续使用 `/templates`。
- 从编辑页进入模板页时，路由附带 `resumeId` 查询参数。
- 从工作台进入时不携带 `resumeId`。

### 4.2 页面结构

模板页由以下区域组成：

1. 顶部导航区域
2. 筛选工具条
3. 模板卡片网格
4. 预览弹窗
5. 使用模板选择框

### 4.3 顶部导航区域

- 保留返回入口。
- 保留产品标题，但弱化与编辑页头部的混用感。
- 不复用编辑页的导出类操作，避免语义污染。

### 4.4 筛选工具条

工具条包含三类控件：

- 分类标签：`全部`、按模板分类值映射出的分类标签。
- 搜索输入：按模板名称、描述、关键词匹配。
- 排序下拉：`推荐优先`、`名称`、`最近使用`。

移动端处理方式：

- 工具条拆成上下两行。
- 搜索输入独占一行或与排序控件上下堆叠。
- 模板卡片降为单列。

### 4.5 模板卡片

每张卡片包含：

- 实时缩略图区域
- 模板名称
- 模板描述
- 分类或推荐标签
- `预览` 按钮
- `使用此模板` 按钮

卡片不展示静态封面图，不落盘缓存预览图片。

## 5. 数据模型设计

### 5.1 模板元数据增强

当前 `TemplateMetadata` 只包含基础字段，无法支撑产品级筛选与排序。需要补充以下能力：

- `categoryLabel`：用于 UI 展示的分类名称。
- `keywords` 或 `tags`：用于搜索匹配。
- `recommendedOrder`：用于推荐排序。

说明：

- `category` 继续保留原有枚举值，用于内部识别模板类型。
- `categoryLabel` 用于向用户显示中文分类名，避免直接暴露内部枚举。
- `recommendedOrder` 数值越小优先级越高。

### 5.2 演示数据

新增一份内置 `demoResumeData`，作为模板页所有预览与缩略图的唯一数据源。

要求：

- 演示数据字段完整，能覆盖头像、简介、经历、项目、教育、技能等主要模块。
- 内容长度适中，保证不同模板在缩略图中都能形成稳定版式。
- 与当前编辑态数据完全解耦。

### 5.3 最近使用记录

新增轻量本地存储键，例如：

`sea-resume_template-usage`

存储内容为模板使用时间映射，例如：

```json
{
  "modern": 1774850000000,
  "professional": 1774860000000
}
```

设计原则：

- 只记录模板 UI 使用偏好，不写入简历正文数据。
- 不修改现有 `LocalStorageAdapter` 与 `FileSystemAdapter` 的存储职责。
- 仅在模板被成功“创建新简历”或“应用到当前简历”后更新记录。

## 6. 组件与模块边界

### 6.1 模板组件注册表

将当前分散在多个文件中的模板映射抽为公共模块，例如：

- `src/components/preview/template-registry.ts`

该模块负责：

- 输出模板 ID 到组件的统一映射。
- 提供模板组件查找函数。
- 被编辑页、预览面板、模板页共用。

目的：

- 消除 `src/views/Editor.vue` 与 `src/components/preview/PreviewPanel.vue` 中重复维护的映射表。
- 避免新增模板时漏改入口。

### 6.2 模板卡片缩略图组件

建议新增专用卡片预览组件，职责如下：

- 接收 `templateId` 与 `demoResumeData`
- 在固定比例容器中挂载对应模板组件
- 控制缩放、裁剪、交互屏蔽
- 在渲染失败时显示占位态

该组件只服务模板页，不直接承担编辑器预览职责。

### 6.3 大预览弹窗组件

建议将大预览弹窗拆为模板页内部组件或局部逻辑，职责如下：

- 渲染选中模板的完整大预览
- 展示模板名称、描述、分类标签
- 提供 `创建新简历`、`应用到当前简历` 按钮
- 根据是否有 `resumeId` 决定按钮可用状态

### 6.4 使用模板选择框

`使用此模板` 的选择框应采用明确动作按钮，而非复用 `confirm/cancel` 语义。

需要提供三种结果：

- 创建新简历
- 应用到当前简历
- 取消

若当前没有 `resumeId`：

- `应用到当前简历` 按钮禁用
- 显示说明文案：`需从编辑页进入`

## 7. 交互流程

### 7.1 页面初始化

1. 读取模板元数据。
2. 初始化筛选状态：
   - 分类：`全部`
   - 搜索关键词：空
   - 排序：`推荐优先`
3. 读取最近使用映射。
4. 渲染卡片网格。
5. 缩略图逐个挂载。

### 7.2 模板筛选与排序

筛选顺序：

1. 分类过滤
2. 关键词过滤
3. 排序规则应用

排序规则定义：

- `推荐优先`：按 `recommendedOrder` 升序，其次按名称。
- `名称`：按模板名称字典序。
- `最近使用`：按模板最近成功使用时间倒序；无记录的模板排在后面，再按推荐顺序兜底。

### 7.3 预览流程

1. 用户点击卡片 `预览`。
2. 打开大预览弹窗。
3. 使用同一份 `demoResumeData` 渲染对应模板。
4. 弹窗底部提供明确操作按钮。

说明：

- 大预览与卡片缩略图使用相同模板组件，仅容器尺寸不同。
- 预览行为不更新最近使用记录。

### 7.4 使用模板流程

#### 从工作台进入

1. 用户点击 `使用此模板`。
2. 打开选择框。
3. 强调主动作 `创建新简历`。
4. `应用到当前简历` 置灰并提示需从编辑页进入。
5. 成功创建后跳转到新简历编辑页，并更新最近使用记录。

#### 从编辑页进入

1. 用户点击 `使用此模板`。
2. 打开选择框。
3. 用户选择：
   - `创建新简历`
   - `应用到当前简历`
4. 执行动作成功后更新最近使用记录。
5. 根据动作跳转或留在当前编辑流程。

### 7.5 默认标题规则

创建新简历时，初始标题按以下模式生成：

`<模板名>简历 - <日期>`

要求：

- 仅作为初始值。
- 后续仍可通过现有重命名机制修改。

## 8. 异常与降级策略

### 8.1 缩略图渲染失败

- 单张卡片降级为占位态。
- 显示提示文案：`预览生成失败`。
- 不影响其他模板卡片正常渲染。

### 8.2 大预览渲染失败

- 弹窗内显示错误占位。
- 提供关闭与重试方式。
- 不导致整个模板页崩溃。

### 8.3 创建或应用失败

- 使用 `ElMessage.error` 提示明确错误。
- 不更新最近使用记录。
- 不错误跳转。

### 8.4 用户取消操作

- 关闭弹窗或选择框视为正常取消。
- 不提示错误信息。

## 9. 技术约束与实现注意事项

- 模板页筛选与排序全部在前端同步完成。
- 不将缩略图渲染结果持久化到 `ResumeMeta.thumbnail`。
- 不污染现有存储适配器职责边界。
- 不在模板页中引入与导出、打印无关的编辑器动作。
- 模板预览组件必须屏蔽编辑态交互，避免在模板页点击时误触内部拖拽或模块选择逻辑。

## 10. 测试与验收

### 10.1 自动验证建议

至少覆盖以下场景：

- 筛选与排序逻辑正确性。
- 无 `resumeId` 时 `应用到当前简历` 按钮禁用状态。
- 选择框动作分流：
  - 创建新简历
  - 应用到当前简历
  - 取消
- 预览渲染失败时的降级表现。

### 10.2 手工验证建议

至少执行以下回归：

- 桌面端模板页浏览。
- 移动端模板页浏览。
- 从工作台进入模板页并创建新简历。
- 从编辑页进入模板页并应用到当前简历。
- 预览弹窗打开、关闭、切换模板。
- 搜索、分类、排序组合操作。

## 11. 实施顺序建议

建议实现顺序如下：

1. 提取公共模板注册表。
2. 定义演示数据与模板元数据增强字段。
3. 实现模板卡片实时缩略图组件。
4. 重写模板页筛选、搜索、排序逻辑。
5. 实现大预览弹窗。
6. 实现明确动作的使用模板选择框。
7. 接入最近使用记录。
8. 补充自动验证与手工验证。

## 12. 风险

- 模板组件本身带有编辑态交互逻辑，直接用于模板页时可能产生多余点击反馈，需要在模板页容器层做交互隔离。
- 实时缩略图可能带来渲染开销，需要控制挂载数量与缩放方式。
- 当前模板页头部复用了编辑器头部思路，若继续强行复用，会造成语义混乱，建议局部重写模板页头部。

## 13. 结论

本设计采用“升级型图库”方案，在保留现有模板页认知成本最低的前提下，完成以下关键增强：

- 实时模板缩略图
- 完整大预览弹窗
- 明确的模板使用动作选择
- 分类、搜索、排序能力
- 基于真实成功使用的最近使用排序

设计确认后，下一步应进入实现计划拆解，而非直接无序改代码。
